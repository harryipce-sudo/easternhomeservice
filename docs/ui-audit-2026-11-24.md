# Eastern Home Service UI/UX audit — 24 November 2026

## Scope and evidence

Reviewed the live tracker in Chrome with populated shared data (86 jobs), and inspected the implementation in `tracker.html`, `tracker.css`, `invoice-workspace.css`, `client-portal-tracker.css`, and `tracker.js`.

Captured the live Jobs board at desktop, tablet (834 × 1194), and mobile (390 × 844), plus the Today dashboard. The live board, address-copy controls, card menu, workflow stages, and financial metadata were present.

## What is already working well

- The top-level navigation is clear and the board/register switch is easy to find.
- The existing workflow stages, drag handles, action menus, copy-address control, and directions control are exposed to assistive technology with useful labels.
- Financial information is available directly on cards, and the current board preserves the user’s configured stages and card ordering.
- The Today view already groups work, attention items, and workflow queues in a helpful way.

## Actual problems observed

1. **The board is squeezed at normal desktop widths.** Five or more columns share the available width, while long property addresses, two address-action icons, and the overflow action are all inside the title row. This makes card headings wrap into awkward short lines and gives the controls more visual weight than the job itself.
2. **Tablet reflow is not intentional.** At 834 px, every column becomes very narrow while the board continues horizontally. Address headings break into many lines, action icons crowd the header, and each column introduces its own visible scrollbar.
3. **Mobile does not provide a practical board-navigation pattern.** At 390 px the first column consumes the screen, the horizontal board is not obvious, and cards still show a desktop-density layout. The bottom navigation remains useful, but the board needs a deliberate single-column/lane-navigation treatment.
4. **There is too much nested scrolling.** The page, horizontal board, and each fixed-height column can all scroll. This makes it easy to lose the current lane and harder to use drag-and-drop confidently.
5. **Card hierarchy is inconsistent.** Address, client, date, amount, markup, missing values (`-`), and actions compete in a small space. Markup pills repeat strongly across almost every card, even where they are secondary information.
6. **Workflow colour is over-applied.** Column tints, coloured headings, due-date pills, payment labels, and markup labels all compete. Status should be visible, but primarily through small accents and badges rather than broad saturated surfaces.
7. **Toolbar controls do not have a clear responsive priority.** Search, sorting, workflow filtering, payment filtering, view switching, and totals wrap into multiple competing rows at smaller widths.
8. **The stylesheet needs consolidation before broad visual work.** `tracker.css` contains successive theme and component overrides for the same selectors (for example `.sidebar`, `.job-board`, `.board-column`, `.board-card`, and drawer styles). This makes a small visual change risky and difficult to reason about.

## Accessibility and interaction risks

- The current compact address actions are labelled and functionally separate from card dragging; retain that event isolation during the redesign.
- At tablet and mobile widths, action targets and wrapped headings become crowded. The redesign should use at least 40–44 px touch targets on mobile and move secondary actions out of the address text line.
- Dense colour coding should not be the only status signal. Keep text labels and ensure focus states remain visible.
- Drag-and-drop must remain available, but the board should also provide a clear non-drag route for status changes or card editing where practical.

## Recommended first implementation pass

1. Introduce a token-based board/card layer at the end of the current stylesheet, rather than rewriting workflows or financial code.
2. Make lanes 304–320 px on desktop and use one horizontal board scroller; remove per-lane fixed-height scrolling.
3. Rebuild the card layout around address, client, schedule/amount, and a compact footer; reserve the overflow menu for secondary actions and keep Copy/Directions in a small dedicated action cluster.
4. At tablet/mobile, switch to a lane picker or one-column board view so a job card retains a readable width and practical tap targets.
5. Apply the same token, typography, control, table, and dialog rules to the drawer, invoices, and financial views only after the board pass is accepted.

## Evidence limits

This audit was visual and code-based. It did not modify, submit, delete, move, or create any live job or invoice record. Drag-and-drop, persistence, calculations, email, and invoice flows still require regression testing after the preview implementation is built.
